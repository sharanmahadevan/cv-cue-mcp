## Session and system

### `cvcue_session_info`

Show the current CV-CUE API session: logged-in key/user, role, customer, timezone and allowed locations, plus the server base URL and version. Good first call to confirm connectivity.

_No parameters._

### `cvcue_server_info`

CV-CUE server version, supported API module versions and server health. Use to check whether an endpoint/version is available on this server.

_No parameters._

## Connections (hosted, signed-in users)

## Full API discovery

### `cvcue_api_modules`

List the CV-CUE API modules with operation counts (step 1 of API discovery). Modules group related resources: session, locations, manageddevices (your APs), aps (all detected APs incl. rogues), clients, configuration (policies), deviceconfiguration (SSID/role/RADIUS profiles, device templates), events, troubleshooting, system, reports, analytics, switches, users, ... Pass a module name as `module` to cvcue_api_search.

_No parameters._

### `cvcue_api_search`

Search CV-CUE API endpoints (step 2 of API discovery). Matches every word of `keyword` against path, operationId, summary and description. Use cvcue_api_schema on a result before cvcue_api_execute.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `keyword` | string | **required** | Search term, e.g. 'reboot', 'ssid', 'packet capture', 'rogue' |
| `module` | string | `None` | Optional module filter (from cvcue_api_modules) |
| `method_filter` | string | `None` | Optional HTTP method: GET/POST/PUT/DELETE |
| `limit` | int | `40` | Max results (default 40) |

### `cvcue_api_schema`

Get parameters, request body and response schema for one endpoint (step 3 of API discovery). Component $refs are inlined up to ref_depth.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `path` | string | **required** | API path exactly as in search results, e.g. '/clients/{macaddress}/associationhistory' |
| `method` | string | `'GET'` | HTTP method |
| `ref_depth` | int | `3` | How deep to inline $ref schemas (0-6, default 3) |

### `cvcue_api_execute`

Execute ANY CV-CUE API call (step 4 of API discovery). Paths are relative to the API base URL (…/wifi/api). Most list endpoints page with startindex (0-based offset) + pagesize, and accept locationid to scope results to a location subtree (see cvcue_list_locations). Examples: GET /system/version GET /manageddevices/aps query_params={"pagesize": 20, "active": true} GET /clients/{macaddress}/associationhistory path_params={"macaddress": "AA:BB:CC:DD:EE:FF"} GET /troubleshooting/clientevents query_params={"fromtime": <epoch ms>, "pagesize": 50} Large responses: many GETs accept fields=[...] for a selective fetch (a field that doesn't support it fails with SELECTIVE_FETCH_OR_UPDATE_NOT_SUPPORTED_FOR_FIELD — drop that field and retry). /deviceconfiguration/devicetemplates is huge unless you pass modelspecific=false. Oversized results are refused with a shape preview. Secret values (passphrases, RADIUS secrets...) come back as ***REDACTED***. Never send that placeholder back in a write body — omit the field or supply the real value. Non-GET calls require writes to be enabled for this connection.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `method` | string | **required** | HTTP method: GET, POST, PUT, DELETE |
| `path` | string | **required** | API path, e.g. '/manageddevices/aps' or '/clients/{macaddress}/snapshots' |
| `path_params` | object | `None` | Substitutions for {placeholders} in path |
| `query_params` | object | `None` | Query parameters (lists become repeated params) |
| `body` | object \| any[] \| string | `None` | JSON request body for POST/PUT/DELETE |
| `version` | string | `None` | Optional module API Version header (default: server latest) |
